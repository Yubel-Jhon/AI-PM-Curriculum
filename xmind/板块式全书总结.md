# 产品经理就业知识体系 · 全书总结

## 0 全景与使用说明
### 一句话主线
- ①需求输入 → ②变成方案 → ③推进交付 → ④数据验证 → ⑤判断方向
- ⑥沟通让这一切落地，⑦素养决定做到多深
- AI 再加一层：⑧能不能做 → ⑨好不好 → ⑩守底线 → ⑪算清账
### 通用原则
- 产品 = 用户价值 × 商业价值的平衡点，一个都不能少
- 听用户的，但不要照着做
- 少做就是多做
- 文档、流程、敏捷、KPI 都只是手段
- 管理靠权力，领导靠魅力
- AI 时代新增：模型有幻觉、会翻车，是常态不是 bug，必须兜底

## 板块① 需求能力 · 翻译
### 在干什么
- 把用户说的话，翻译成产品的定义
### 术语（1-7）
- 1 用户需求 vs 产品需求：用户要的是方案，产品要的是真实需求
- 2 需求采集四象限：定性/定量 × 说/做
- 3 DNA 检测：定属性 → 商业价值 → 实现难度 → 性价比
- 4 性价比：商业价值 ÷ 实现难度（人天）
- 5 需求打包 / PK：资源约束下按性价比并成项目
- 6 听用户的但不要照着做：听是采集，不照着做是转化
- 7 分·总·分：拆开看属性 → 归并共性 → 回场景验证
### 全书支撑
- 福特「更快的马」→ 汽车
- 索尼「说喜欢黄色，带走黑色」
- 猪骨头火锅被两个馒头满足
### 一句话归纳
- 需求能力 = 翻译能力，从「用户要的」到「真正该做的」
### AI 增量
- 板块⑧ 把「翻译」升级为「翻译成模型任务」

## 板块② 规划设计 · 落地
### 在干什么
- 把需求落到可执行方案：定义、PRD、原型、流程图、版本规划
### 术语（8-16）
- 8 产品：解决用户与公司双方问题的平衡点
- 9 产品经理：发现并描述问题的人
- 10 大产品观：凡影响体验和价值的一切都属 PM 职责
- 11-14 BRD/MRD/PRD/FSD：值不值 → 给谁 → 做什么 → 怎么做
- 15 文档阶梯逻辑：BRD → MRD → PRD → FSD 逐层细化
- 16 文档只是手段：服务于沟通，不为写而写
### PRD 七板块
- 文档头与目标 / 范围与角色 / 场景与需求清单 / 功能详述 / 非功能需求 / 验收标准 / 版本与遗留
### 一句话归纳
- 规划设计 = 落地能力，把想法变可交付的约定
### 改造点（AI）
- AI-native PRD 五要素：评估标准、模型约束、数据需求、埋点清单、防护兜底

## 板块③ 项目管理 · 交付
### 在干什么
- 把项目按时做成：排期、协调、盯进度、控风险
### 术语（17-25）
- 17 项目：只做一次、多任务互相关联的工作
- 18 多快好省 TRQ：范围/时间/品质/资源不可兼得
- 19 WBS：任务自上而下分解到可估算粒度
- 20 Kick Off：启动会对齐目标/资源/分工/节奏
- 21 三次评审：需求/设计/测试评审，防病优于治病
- 22 敏捷开发：迭代不变、小步快跑、快速反馈
- 23 三边六拍：边设计边施工边修改 + 六拍式失败
- 24 计划与控制：先有计划，再控制偏差
- 25 做正确的事 vs 正确地做事：PM 靠想，项目经理靠做
### 一句话归纳
- 项目管理 = 交付能力，多快好省的平衡术
### 改造点（AI）
- 分层发布、回滚/降级/Kill Switch、Prompt 版本控制、漂移监控

## 板块④ 数据分析 · 验证
### 在干什么
- 用数据验证决策：定指标、看漏斗、做 A/B、用留存说话
### 术语（26-30）
- 26 KPI：战略的具体表现，手段而非目的
- 27 北极星指标：代表长期价值的核心指标
- 28 漏斗与转化：每层流失都是优化机会
- 29 留存 / 活跃：留存是产品价值的照妖镜
- 30 A/B 测试：随机分两组，一次只改一个变量
### 一句话归纳
- 数据分析 = 验证能力，从拍脑袋到用数据说话
### 改造点（AI）
- 模型指标看板：离线 F1 + 在线采纳率/接管率，两套都盯

## 板块⑤ 商业战略 · 方向
### 在干什么
- 判断做什么、值不值得做
### 术语（31-36）
- 31 可行性三步曲：我们在哪儿 → 去哪儿 → 怎么去
- 32 PEST：政治/经济/社会/技术四维扫环境
- 33 SWOT：优势/劣势/机会/威胁 → 策略组合
- 34 价值观 → 使命 → 愿景 → 战略：层层炼成
- 35 使用用户：化解销售 vs 产品指标矛盾
- 36 炮灰版 / 水平营销：价格锚点 + 找新维度
### 一句话归纳
- 商业战略 = 方向能力，选对战场比打赢更重要
### 改造点（AI）
- 数据飞轮与防御性（详见板块⑪）

## 板块⑥ 沟通协作 · 影响力
### 在干什么
- 推动一群没职权的人把事做成——无授权领导
### 术语（37-42）
- 37 无授权领导：靠专业话语权 + 影响力
- 38 矩阵型组织：职能 + 项目双线
- 39 接口人：团队间单一对接人，过滤噪音
- 40 大产品 / 大设计 / 大团队：放大到全链路
- 41 管理靠权力，领导靠魅力
- 42 猎人 vs 农民：猎人管事盯结果，农民管人耕过程
### 一句话归纳
- 沟通协作 = 影响力，靠专业、靠谱、让人愿意跟你干
### 改造点（AI）
- 对技术讲验收口径、对高管讲单位经济、对销售讲边界、对合规讲风险

## 板块⑦ 学习与自我修养 · 底色
### 在干什么
- 决定前面六块能走多深的底层素质
### 术语（43-48）
- 43 自我修养四件套：爱生活、有理想、会思考、能沟通
- 44 解决问题通用思路：万能提问模板
- 45 少做就是多做：100% 质量做 75% 数量
- 46 生态隐喻：云雨 → 河流 → 动植物 → 阳光 → 大地
- 47 用户与商业目标平衡：一个都不能少
- 48 产品经理主义：把产品思维普世化
### 一句话归纳
- 自我修养 = 底色能力，底色决定天花板
### 改造点（AI）
- 持续追踪 AI 进展：跟着模型发布节奏、做小实验

## 板块⑧ AI 技术认知 · 判断能不能做
### 在干什么
- 把业务需求翻译成模型任务，判断边界
### 术语（49-54）
- 49 模型类型与能力边界：边界内做深，边界外别硬做
- 50 大模型基础：Transformer / 预训练 / 微调 / Prompt
- 51 RAG：先检索再生成，开卷考试
- 52 Agent / MCP / 工具调用：多步任务自主调用工具
- 53 上下文窗口与延迟：窗口大 ≠ 什么都塞
- 54 幻觉：一本正经编造，无法根除只能缓解
### 一句话归纳
- AI 技术认知 = 判断能力

## 板块⑨ 模型评估与数据闭环 · 验证好不好
### 在干什么
- 先定义「怎么算好」，再上线验证，再数据喂养迭代
### 术语（55-59）
- 55 评估集 / 金标准集：人工标注标准答案，不参与训练
- 56 离线指标：准确率 / 召回率 / F1
- 57 在线指标：采纳率 / 任务完成率 / 人工接管率
- 58 数据闭环：采集 → 清洗 → 标注 → 评估 → 迭代
- 59 价值归因：判断指标变化是不是模型带来
### 一句话归纳
- 模型评估 = 验证能力，从「感觉还行」到「有数字证明」

## 板块⑩ 信任安全与伦理合规 · 守底线
### 在干什么
- 功能做出来之前，先想清楚怎么不闯祸
### 术语（60-65）
- 60 公平性：不同人群表现不能明显偏差
- 61 可解释性：为什么给这个结果能说清
- 62 隐私保护：最小化采集、脱敏、授权、合规前置
- 63 内容安全：前置过滤 + 后置拦截 + 人工巡查
- 64 Red Teaming：对抗性攻击测试主动找漏洞
- 65 发布门槛 Release Gates：安全 + 兜底 + 指标 + 监控
### 一句话归纳
- 信任安全 = 底线能力，先想清楚怎么不闯祸

## 板块⑪ AI 产品经济学 · 算清账
### 在干什么
- 成本当产品参数管，先算清账再做
### 术语（66-70）
- 66 Token / 推理成本：每次请求都花钱
- 67 单位经济：收入 − 成本，LTV > CAC + 推理成本
- 68 定价建模：成本打底 + 价值锚定 + 版本分层
- 69 模型选型成本权衡：成本 / 延迟 / 精度 / 上下文
- 70 数据飞轮与防御性：越用数据越多 → 越好 → 用户越多
### 一句话归纳
- AI 产品经济学 = 算账能力
