# AI-PM 面试方法论

> 数据来源：公开面经（牛客/CSDN/mianlingai/腾讯云/B站标题）+ 本地 AI-PM-Curriculum（术语 49–70）。
> 证据强度：一手口述（牛客实录）＞ 二手转述（公众号/博客）＞ 框架总结（本文归纳）。
> 本文每类结论都标了证据强度，别把二手当一手。

---

## 0. 核心结论（3 句话）

1. **AI-PM 面试考的不是背名词，是技术边界认知 + 取舍判断力。** 会背 RAG 定义但说不清「什么场景用 RAG 不用微调」，技术轮必挂。
2. **挂点高度共性**：①只会背不会判断 ②项目经不起「为什么这么决策、数据怎么看」深挖 ③表达没框架没逻辑。
3. **万能答题结构**：概念绑定场景 → 选型给理由 → 风险给兜底。三个环节缺一个就掉分。

## 1. 概念层（复用本地 curriculum 术语 49–70）

概念不用背全，**每个概念配一个场景 + 一句取舍理由**即可。下面四板块是 AI 增补层核心，通用底座（需求/规划/项目/数据/商业/沟通）不在本文展开。

### ⑧ AI 技术认知 —— 判断「能不能做」

| 术语 | 一句话 | 面试常考问法 |
|---|---|---|
| 模型类型与能力边界 | 边界内做深做透，边界外别硬做 | 「这件事 AI 能不能做？」 |
| 大模型基础 | Transformer / 预训练 / 微调 / Prompt | 「预训练和微调区别？」 |
| RAG | 先检索再生成，开卷考试 | 「RAG 是什么？为什么用它？」 |
| Agent / MCP / 工具调用 | 模型自主规划 + 调工具完成多步 | 「Agent 最易翻车在哪？」 |
| 上下文窗口与延迟 | 窗口大 ≠ 什么都塞；延迟决定交互形态 | 「长文档怎么塞进窗口？」 |
| 幻觉 | 一本正经编造，无法根除只能缓解 | 「怎么解决幻觉？」 |

### ⑨ 模型评估与数据闭环 —— 验证「做得好不好」

| 术语 | 一句话 | 面试常考问法 |
|---|---|---|
| 评估集 / 金标准集 | 人工标注标准答案，不参与训练 | 「怎么验收 AI 功能？」 |
| 离线指标 | 准确率/召回率/F1，评估集上跑 | 「上线前怎么测？」 |
| 在线指标 | 采纳率/任务完成率/人工接管率 | 「上线后看什么？」 |
| 数据闭环 | 采集→清洗→标注→评估→迭代 | 「数据闭环怎么搭？」 |
| 价值归因 | 指标变化是模型还是别的因素 | 「效果提升到底是不是模型的功劳？」 |

### ⑩ 信任安全与伦理合规 —— 守住「底线」

| 术语 | 一句话 | 面试常考问法 |
|---|---|---|
| 公平性 | 对不同人群不能明显偏差 | 「模型有偏见怎么办？」 |
| 可解释性 | 为什么给这个结果能说清 | 「用户问为什么，怎么答？」 |
| 隐私保护 | 最小化采集、脱敏、授权、合规前置 | 「PII 怎么处理？」 |
| 内容安全 | 前置过滤 + 后置拦截 + 人工巡查 | 「黄暴内容怎么挡？」 |
| Red Teaming | 对抗性攻击测试，主动找漏洞 | 「上线前怎么压测安全？」 |
| 发布门槛 | 不过关不能发：安全+兜底+指标+监控 | 「什么条件才能上线？」 |

### ⑪ AI 产品经济学 —— 算清「值不值、赚不赚」

| 术语 | 一句话 | 面试常考问法 |
|---|---|---|
| Token / 推理成本 | 每次请求都产生真实成本 | 「这个功能赚不赚钱？」 |
| 单位经济模型 | 收入−成本，LTV > CAC+累计推理成本 | 「定价怎么定？」 |
| 定价建模 | 成本打底 + 价值锚定 + 版本分层 | 「API/订阅/私有化怎么选？」 |
| 模型选型成本权衡 | 成本/延迟/精度/上下文四维 | 「大模型还是小模型？」 |
| 数据飞轮与防御性 | 越用数据越多→模型越好→用户越多 | 「护城河是什么？」 |

## 2. 六大题型 + 破题框架

| 题型 | 识别信号 | 破题框架 | 一句话心法 |
|---|---|---|---|
| **项目题** | 「介绍下你做的项目」 | 背景→目标→职责→关键决策→难点→结果 | 讲「决策和取舍」，不是讲流程 |
| **概念题** | 「什么是 RAG / 幻觉」 | 类比→定义→选型理由→边界→场景举例 | 概念必须绑场景，否则=背名词 |
| **方案/业务题** | 「给豆包设计 XX」 | 红线失败→运营KPI→用户旅程+逃生阀→评测计划 | 先定「绝不能发生什么」 |
| **估算题** | 「估算 ChatGPT 日活」 | 拆解公式→假设→量级校验 | 量级对即可，过程比结果重要 |
| **追问题** | 你答完后继续问「为什么」 | 用「数据/取舍理由/复盘」回，不重复流程 | 追问考的是判断，不是知识 |
| **压力题** | 节奏快、反馈冷、被质疑 | 承认→给依据→转方案，不硬刚 | 被质疑「意气用事」时先接住再给数据 |

## 3. 高频题库（问题 + 答题要点 + 追问链 + 雷区）

> 题型标注：项目/概念/业务/估算/追问/压力。杀伤力：高=答错直接挂，中=答差掉分，低=锦上添花。

### A. 技术认知类（最高频、淘汰率最高）

**Q1. RAG 和微调怎么选？（概念，杀伤力高，高频）**
- 要点：微调=把知识固化进参数，黑盒，更新要重训，贵；RAG=知识外挂向量库，换库不换脑，可溯源。
- 话术：「微调把整本书背下来，RAG 是开卷考试。业务知识更新比翻书还快，肯定查资料更划算。实际项目 RAG-First，跑通后发现语感/格式不达标再上微调。」
- 追问链：为什么 RAG-First？→ 成本低、可插拔、可溯源；RAG 效果不好怎么办？→ 切片/召回/重排三层排查。

**Q2. 怎么解决幻觉？（概念，杀伤力高，高频）**
- 要点：必答「两类幻觉来源」——检索层幻觉（没召回到内容，模型自己编）vs 生成层幻觉（召回到了但没照着说）。
- 话术：「幻觉不是撒谎，是模型生成了『看起来合理的下一个词』。先分清是检索没捞到还是生成没照抄——两类根源不同解法不同。低成本四步：Prompt 强约束→检索质量门控（Rerank 低于阈值拒答）→生成后引用核查→结构化输出强制溯源。生产系统前两个必须上。」
- 雷区：只说「检索做好就不会幻觉」——这是外行话。

**Q3. 大模型 vs 小模型怎么选？（概念，杀伤力中，高频）**
- 要点：从参数量、数据需求、泛化能力三层对比；落地看成本/延迟/精度/上下文四维。
- 话术：「通用能力大模型强，但成本高、延迟高；垂直任务小模型+LoRA 够用且便宜。看四维：成本、延迟、精度、上下文窗口。能离线跑、低延迟的场景用小模型，复杂推理用大模型。」

**Q4. Transformer 核心创新是什么？（概念，杀伤力中，中频）**
- 要点：自注意力机制（Self-Attention）+ 并行计算，解决 RNN 长序列遗忘问题。
- 一句话：「自注意力让每个词能直接看到所有词，并行计算，解决了 RNN 记不住长序列的问题。」

**Q5. Prompt 工程为什么重要？（概念，杀伤力中，高频）**
- 要点：出现频率超 80%，考的不是「会写 Prompt」，而是把 Prompt 设计和产品目标连起来——System Prompt 如何控制模型性格、拒绝边界、输出格式。
- 话术：「Prompt 是产品的『人设和边界』，System Prompt 决定模型怎么说话、什么不答、输出什么格式。和 UX 目标对齐，不是调几个词。」

**Q6. Agent / MCP / 工具调用怎么理解？（概念，杀伤力中，高频）**
- 要点：Agent=模型自主规划 + 调工具完成多步。最易翻车在「计划」和「反馈」两环。
- 话术：「Agent 最容易出问题的是 Planning（瞎定目标）和 Feedback（给错判断），两环错一个流程就崩。产品视角看四步：需求场景→输入输出映射→Prompt 调优→评测指标+真实效果。」

**Q7. Function Calling 失败率怎么定义可接受？无感降级？（业务，杀伤力高，字节真题）**
- 要点：区分「可重试失败」和「不可重试失败」，定兜底。
- 话术：「先分失败类型——参数解析失败可重试，工具执行失败要降级。可接受失败率看场景：关键操作（转账）趋近 0，非关键（闲聊推荐）可容忍 5-10%。无感降级=失败时静默走默认路径或转人工，不让用户感知到卡壳。」

### B. 产品思维与场景类

**Q8. 怎么设计垂直领域大模型产品？（方案，杀伤力高，高频）**
- 要点：场景→数据→模型→评估→闭环五步。
- 话术：「先圈场景（能不能用、值不值得），再看数据（有没有、质量如何），再选模型，再定评估集，最后数据闭环迭代。别一上来谈模型。」

**Q9. 企业知识库问答 Prompt 模板怎么设计？（方案，杀伤力中，中频）**
- 要点：角色设定 + 上下文注入 + 约束（只答资料内）+ 输出格式 + 拒答边界。

**Q10. 大模型哪些场景会被垂直小模型取代？（业务，杀伤力中，中频）**
- 要点：高频、规则明确、数据充足、低延迟要求的任务（如特定分类、特定抽取）用小模型更划算。
- 话术：「高频、规则明确、数据够、延迟敏感的任务，小模型精度够且成本低一个量级。大模型留给复杂推理和长尾泛化。」

### C. 商业化类

**Q11. API 按量 / SaaS 订阅 / 私有化部署怎么选？（业务，杀伤力中，中频）**
- 要点：按 token 计费适合轻量试用、订阅适合高频稳定、私有化适合安全敏感大客户。
- 话术：「三模式不是互斥，是分层：API 引流、订阅锁定高频用户、私有化吃大客户安全预算。定价=成本打底+价值锚定+版本分层。」

**Q12. 怎么平衡模型性能和用户体验？（业务，杀伤力中，中频）**
- 要点：延迟控制在感知阈值内（如 500ms 内），temperature 调节创造性 vs 稳定性，流式输出优化体感。

### D. 伦理安全类（2025 必考）

**Q13. AI 上线前怎么把关？（概念，杀伤力高，高频）**
- 要点：红队测试 + 安全检查 + 兜底 + 发布门槛 + 分层发布。
- 话术：「先定义红线失败——什么绝对不能发生，再设运营 KPI（延迟/兜底率/漂移检测频率），再设计逃生阀（human-in-the-loop 节点），最后定评测计划。」

**Q14. Prompt 注入攻击怎么防？（概念，杀伤力中，中频）**
- 要点：三层防御——技术层（输入过滤、RLHF 对齐）、产品层（身份验证、日志审计）、运营层（伦理委员会、红线规则）。

## 4. 话术模板库

### 4.1 项目讲述模板（对抗「深挖」）

```
背景：一句话业务背景 + 目标数字
目标：这个项目要解决什么、成功标准是什么
职责：你在里面的具体角色（别用「我们」，用「我」）
关键决策：2-3 个你做的技术/产品取舍（为什么选 RAG 不用微调、为什么这个模型）
难点：最大的困难 + 你怎么定位的 + 怎么解决的
结果：数据（别只说「上线了」，说「采纳率从 X 到 Y」）
```

> 雷区：讲流程不讲决策、用「我们」模糊个人贡献、结果没数据。字节 70%+ 面试含项目深挖，深挖问的全是「为什么这么决策、数据怎么看」。

### 4.2 概念题回答模板

```
1. 类比（一句话，让对方秒懂）：RAG=开卷考试
2. 定义（一句准确的话）
3. 选型理由（什么场景用它/不用它）
4. 边界（它做不到什么）
5. 场景举例（绑一个真实业务）
```

### 4.3 追问接法模板

追问考的是判断不是知识，用三类弹药接：
- **数据**：「这个决策的依据是 XX 指标从 A 变到 B」
- **取舍理由**：「当时在 A 和 B 之间选了 A，因为成本/时间/风险」
- **复盘**：「如果重做，我会先做 XX」

> 雷区：追问时重复上一段流程描述、说「这个我不太清楚」后沉默、被质疑时硬刚。

### 4.4 方案题模板（生成式 AI 产品设计题，来自 Google/Meta/Anthropic 面经）

```
1. 先定义红线失败（什么绝对不能发生）
2. 设运营 KPI（延迟、兜底率、漂移检测频率）
3. 画用户旅程 + 设逃生阀（人工介入点）
4. 提评测计划（A/B 测什么、怎么衡量危害）
```

### 4.5 自我介绍模板（避流水账雷区）

```
60 秒内：一句话定位 → 1 个能说清的项目 → 为什么转/为什么适合 AI-PM → 一句收尾钩子
```
> 雷区（面经实证）：自我介绍讲几分钟流水账直接扣分。

## 5. 总结对比看板

### 5.1 大厂面试风格对比（二手转述，参考）

| 公司 | 风格 | 高频考点 | 典型挂点 |
|---|---|---|---|
| **字节** | 技术深挖、追问密 | RAG 选型、项目决策、数据闭环、竞品（豆包）差异化 | 项目经不起深挖、Function Calling/降级方案答不上 |
| **阿里/蚂蚁** | 压力面、交叉面、HR 权重高 | 微调方式+时间点+基模、效果提升多少、模型路由策略 | 被质疑「意气用事」后崩、HR 面「十动然拒」 |
| **百度** | 偏业务、场景重做题 | 场景+大模型重做一遍、AI 应用自己的思考 | 「一问三不知」、表达没逻辑没亮点 |

### 5.2 核心概念对比

| 维度 | RAG | 微调 Fine-tuning | Prompt 工程 |
|---|---|---|---|
| 知识来源 | 外部向量库（动态） | 模型参数（固化） | 无（临时注入） |
| 更新成本 | 低，换库即可 | 高，重训 | 低，改词即可 |
| 可溯源 | 强（能指到 chunk） | 弱（黑盒） | 无 |
| 适合场景 | 知识更新快、需溯源（客服/问答） | 垂直领域深度适配、格式稳定 | 通用模型快速试错 |
| 一句话 | 开卷考试 | 把书背下来 | 临时夹带小抄 |

### 5.3 幻觉两类来源对比

| 类型 | 根源 | 解法 |
|---|---|---|
| 检索层幻觉 | 没召回到相关内容，模型凭训练知识编 | 提高召回（切片/多向量/Rerank）、知识覆盖补齐 |
| 生成层幻觉 | 召回到了，但没严格照着说，自己加料 | Prompt 强约束、引用核查、结构化输出强制溯源 |

### 5.4 离线指标 vs 在线指标

| 类型 | 定义 | 指标 | 时机 |
|---|---|---|---|
| 离线 | 评估集上跑 | 准确率/召回率/F1/BLEU/ROUGE | 上线前 |
| 在线 | 真实用户行为 | 采纳率/任务完成率/人工接管率 | 上线后 |

### 5.5 最容易挂的 5 类人（一手+二手归纳）

1. 只刷题背定义，解释不了技术选型（RAG vs 微调）
2. 简历项目经不起「为什么这么决策、数据怎么看」深挖
3. 表达没框架、自我介绍流水账
4. 对 AI 产品没真实使用体验、只会复述概念
5. 操作失误：主动问「对我的评价」、薪资答不当、简历注水

### 字节 AI 产品一面（8 题全录）

1. 平时体验哪些 AI 产品（ChatGPT/Claude/Kimi/豆包），挑一个有亮点的分析交互逻辑背后的产品思维。
2. 在抖音/剪映深度集成 AI 功能（如 AI 生成短视频脚本），需和技术（算法/工程）厘清哪些关键问题？
3. Function Calling 失败率如何定义「可接受失败率」？设计用户无感的降级/补救方案？
4. 上线 AI 新功能后，按次日/首周/首月拆解关注的核心数据？
5. 「数据闭环」对 AI 产品迭代的重要性？结合「优化 AI 文案生成效果」说明如何构建闭环。
6. 为豆包设计高级付费版本，从哪些维度规划核心付费权益？
7. 字节 AI 产品（豆包）相对竞品最该建立的差异化优势？如何通过产品特性实现？
8. 描述一个协调设计/研发/算法/运营推动上线的完整经历，最大协作挑战及解决。

**信号**：字节一面重业务判断（失败率/数据闭环/差异化/付费），技术只到选型层，不像抖音面挖到 GRPO。

### 文远知行 AI 全栈三面（RAG 深挖 · 片段）

- 「我和你」三个字在向量数据库（PGVector）怎么存储？
- Embedding 具体指什么？
- RAG 中的重排有什么作用？
- RAG 有没有更新的玩法？
- 训练模型的全流程（科研部分也考）

**信号**：AI 全栈/偏技术岗会把 RAG 挖到向量存储和重排粒度；产品岗一般到「切片→召回→重排」层即可。

### 5.7.1 面试官视角红黑榜（新手 ❌ vs 专业 ✅，可直接背）

**AI 产品专属 5 问（来源：一位面试官上午面 6 人复盘）**

| 问题 | ❌ 新手答（被 pass） | ✅ 专业答（要点） |
|---|---|---|
| 怎么判断一个 AI 功能该不该做？ | 「用户有需求不就该做吗」 | 需求只是起点，还要看**技术可行性 + 数据可得性 + ROI + 战略一致性**，否则做「技术能实现但没人买单」的功能 |
| 模型上线后效果不达预期怎么办？ | 「赶紧让算法优化模型」 | 先拆维度定位：准确率还是召回率？badcase 集中还是全差？测试集和真实场景分布一致吗？**带着「问题定位+归因+解决建议」再找算法**，别甩锅 |
| 怎么判断 AI 能力达到上线标准？ | 「算法说准确率 90% 了」 | 90% 是单点指标。还要看：关键场景达标率、badcase 对体验影响、响应延迟、**模型失效的兜底方案**、小流量 A/B 验证。技术指标必须绑业务价值 |
| 和技术团队有分歧怎么办？ | 「听技术的/听老板的」 | 摆出双方观点+依据（你选 A 因需求高频市场大，他选 B 因技术成熟落地快），回到业务目标对齐，不硬刚不甩锅 |
| 常用数据工具和方法？ | 「后台看看 + Excel」 | 神策/GrowingIO 漏斗分析、SQL 提数验证假设、Tableau 搭指标看板、A/B 验证效果。**工具是基础，数据驱动决策思维才是考点** |

**通用 PM 5 问（来源：面试官「听到这几句话基本都 pass」）**

| 问题 | 🚫 淘汰答 | ✔ 加分答（要点） |
|---|---|---|
| 产品经理的价值？ | 「整理需求 + 跟开发沟通」 | 连接用户痛点与商业目标：用户访谈+行为数据挖真实需求，平衡技术可行性与资源，推动共识、敏捷验证，达成增长与商业双赢 |
| 怎么判断功能是否成功？ | 「看用户反馈好不好」 | 多维指标：核心行为数据（使用率/完成度）+ 业务结果（留存/转化）+ 体验指标（满意度/任务时长），再定性访谈还原场景 |
| 技术说需求无法实现？ | 「那就让他们想办法」 | 先理解约束本质（资源/架构/成本），回归问题本质找简化方案或分阶段实施（最小原型验证），保持目标导向不执着单一方案 |
| 大量需求怎么定优先级？ | 「按部门重要性排」 | 价值-成本双维 + KANO（基础/期望/兴奋型），评估需求关联性，优先验证核心假设、有网络效应的，资源紧时 A/B 分段验证 |
| AI 对 PM 岗位的影响？ | 「暂时不影响我们」 | AI 重塑能力模型：催生智能体/生成式新形态，要求掌握 Prompt 设计、RAG 优化等新技能，主动学原理+参与实践，传统需求能力与 AI 技术理解结合 |

### 5.7.2 讲项目正确打开方式（面试官视角三层法）

> 面试官原话：「我不在乎你原型多炫酷。候选人不是项目经验不够，是**讲项目的方式跑偏了**——追问三轮短板全暴露。」

所有 AI 项目讲法就三层，**多数人只停在第一层**：

1. **功能层**：你实现了什么 AI 能力（识别/生成/推荐），demo 跑通没——「调过接口」层面
2. **设计层**：需求定义、模型选型、数据策略、评估指标怎么定、badcase 怎么分析——「设计过产品」层面
3. **工程与交付层**：系统稳定性、推理延迟优化、线上 badcase 兜底、用户反馈闭环

**模型选型正确讲法**（最高频深挖点）：
- ❌「我用了 GPT-4，效果不错」——信息量为零
- ✅ 讲全链：业务对效果/成本的核心要求 → 怎么评估不同模型（GPT-4/Claude/Llama/国产）在该场景表现 → 准确率/召回/延迟/成本/数据安全怎么权衡 → **为什么大模型不微调** → 评测集怎么构建、badcase 怎么分析 → 上线后效果对比预期、怎么迭代

### 5.7.3 Agent 设计四层 + 「不确定性管理」（面试官眼中「真懂 Agent」）

> 问「设计一个旅行规划 Agent，你从哪些层面考虑」——满分答不是列功能，是从**根本目标切入**。

1. **规划层**：任务分解用 ReAct 让 Agent 一步步想，还是 CoT 预设关键步骤？这决定 Agent 是「死执行」还是「活思考」
2. **工具层**：不止接入航班/酒店 API，关键在**工具编排策略**——查不到直飞时自动查中转，还是立即问用户？需预设决策流
3. **记忆层**：必须区分**工作记忆 vs 长期记忆**，向量库存长期偏好、规划时主动检索，让 Agent 真正「认识用户」
4. **状态与评估层**：Agent 必须能汇报进度、卡住时触发预设降级方案，而不是沉默或崩溃

**一句话点题**（面试官最吃这句）：「传统产品流程是确定的，像铺铁轨；Agent 是在未知地形自主导航——我的工作不是铺路，而是定义清晰的导航、配好工具、设定遇到断崖时的应急原则。」核心=**对不确定性的管理**。

### 5.7.4 字节两场面经全录（一手）

**面 A：抖音电商 AI 产品（已 oc）——智能客服方向 13 题**

1. 自我介绍 2. 介绍最成功的项目 3. 项目难点 4. **为什么建了向量知识库还要保留 FAQ？** 5. 你具体做了什么 6. **如何构建评测集？** 7. 选什么指标衡量效果 8. **转人工率容易被 mock，怎么处理？** 9. **智能客服如何保证知识时效性？** 10. **微调和 RAG 使用场景区别？** 11. 平时怎么学 AI 知识 12. 为什么离职 13. 对团队的期望

**信号**：智能客服/知识库方向是字节 AI-PM 高频赛道，必考「FAQ vs 向量库」「评测集构建」「转人工率 mock」「知识时效性」四连问——都是 RAG 落地细节，背「切片→召回→重排」不够，要能说清「为什么保留 FAQ、怎么防 mock、知识怎么更新」。

**面 B：字节大模型产品实习——Agent/Skills 方向 11 题**

1. 自我介绍 2. Agent 解决什么问题、怎么做的、最终具备什么能力 3. 你在 Agent 项目里的角色 4. 举一个具体需求例子（内容/实现/交付） 5. 语义理解 badcase 具体是什么、举例用户原输入 vs 误理解 6. 怎么解决 badcase 7. **调 Prompt 时如何确认调好了、评估标准是什么** 8. 服务多个 Agent 时如何评估好坏 9. 调 Prompt 心得 10. **什么场景做思维链（CoT）** 11. **你自己写过 Skills 吗、打算怎么写**

**信号**：Agent 岗必考「badcase 具体化（要举例原输入）」「多 Agent 评估」「CoT 场景」「Skills」——全是 2026 新考点，且要求**举例到用户原输入/误理解的颗粒度**，泛泛而谈必挂。

### 5.7.5 2026 新高频考点（27 届真实拷打实录，必背）

来源：一位 27 届转 AI-PM 连面 9 场的心得，明确「每场必问/几乎必问」的新题：

1. **Agent 是什么？和 workflow 的区别？优缺点？为什么用 workflow 不用 Agent？**（本人最惨烈一次，只会往「规划/执行/记忆/调工具」上凑，被指理论浅薄）
2. **用过什么 AI 工具？对它们的认知？**（考察是否真对 AI 感兴趣——**常备一个万能答案**）
3. **什么是 Skills？让你写 Skills 怎么写？用 AI 生成 Skills 怎么生成？**（万恶的 skills，每场必问）
4. **对 vibe coding 的理解？你亲身做 vibe coding 的感受？**
5. **为什么用 coze 不用更先进的工具？**
6. **龙虾/小龙虾是什么？用过吗？**（几乎必问——**备考时追当下最火的 Agent/Coding 工具**，别只准备去年的）

**备考结论**：Skills、vibe coding、Agent vs Workflow、AI 工具认知这四块是 2026 和往年最大的增量，往年只考 RAG/微调/Prompt，现在往前沿工具和「亲手用 AI 造东西」的体验上移了。没亲手用 Skills/vibe coding 做过东西，很难答出细节。

### 5.7.6 其他公司速览 + 方法论彩蛋

- **AI 独角兽（大模型 PM，一面 mentor + 二面 leader）**：一面 4 题（产品最重要的能力、产品流程、需求定义冲突怎么解决）；二面 4 题（RAG 原理、微调 vs RAG 各自优势、**伦理隐私问题怎么处理**、**数据质量怎么处理**）——伦理+数据质量是二面标配。
- **追觅科技（智能硬件 AI-PM，❌✅ 话术已录）**：核心考「AI 在家庭/商用场景深度落地」的产品逻辑。必考题含「为什么选追觅」「没硬件经验怎么胜任」「具身智能壁垒」「职业规划」——答法全用「理念认同 + 可迁移能力 + 主动补课 + 壁垒=硬件性能×场景数据×端侧模型×交互设计」四段式。
- **百度文心一言（已 offer，0 互联网实习）**：无实习也能上岸，靠「高频使用 ChatGPT/Gemini/Deepseek + 考前做大量对比总结 + 突击大模型原理架构」。**信号：真实 AI 产品使用体验 + 横向对比是 0 经验转行的救命稻草。**
- **5 天速成考点清单**（狠但有用）：①高频考点速记——RAG 链路（召回/重排/向量库选型/切分/上下文）、微调（LoRA 作用/数据构造/评估/过拟合）、Prompt（结构化/Few-shot/CoT/迭代）、评估（准确率/召回/幻觉检测）；②3 道手撕题——AI 交互埋点文档、RAG 效果评估表、微调数据清洗规则；③包装 1 个能打的 AI 项目（说清「核心方案+踩过的坑+解决方法」，逻辑比 demo 重要）。
- **简历包装（转行版）**：功能型 PM 包装成「产品全流程管理+引入 RAG 优化搜索推荐提升准确率 30%」；B/C 端包装成「主动把大模型融入产品（提示词优化客服问答、RAG 整合知识库）」。**一句话：把普通活往「AI 落地 + 数据结果」上靠。**
- **RAG+Rerank 三步**（技术题口径）：①索引（文档切 Chunk + 编码器建向量索引）②检索（问题与 chunks 相似度召回）③生成（以检索上下文为条件生成）。Rerank 通过剔除不相关节点、重排相关节点，在**不牺牲准确率的前提下加速查询**。

## 6. 备考行动清单（按优先级）

1. **挖透一个真实 AI 项目**：选型理由、评估指标、难点+定位过程，写到能经 3 层追问。
2. **背熟 RAG / 幻觉 / 微调选型 / Agent 四个概念的「类比+理由+边界」**，每个绑一个场景。
3. **准备 5 个 AI 产品的真实使用体验**（ChatGPT/Claude/Kimi/豆包），能说清交互逻辑和产品思维。
4. **练方案题框架**：红线失败→KPI→逃生阀→评测计划。
5. **准备 1-2 个「因为伦理/风险叫停项目」的行为故事**（2025 面试新趋势，比「按时上线」故事更吃香）。
6. **补 2026 新考点**：Skills（是什么/怎么写/用 AI 生成）、vibe coding 理解+亲身体验、Agent vs Workflow 区别+选型理由、AI 工具横向认知（常备一个万能答案）——亲手用这些造过 demo，才能答出「举例到用户原输入」的颗粒度。
