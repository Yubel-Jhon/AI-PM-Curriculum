# ⑨ 模型评估与数据闭环 · 深度详解

> 侧重点：验证「做得好不好」。AI 功能上线不是结束，是验证的开始。这一块考的是「你有没有从『感觉还行』走到『有数字证明』」。
> 面试高频送命题：怎么构建评测集、离线/在线指标区别、怎么归因效果提升。

---

## 一、有什么内容（往下走）

### 1. 评估集 / 金标准集 —— 怎么建，不是「人工标注」四个字

**定义**：人工标注的「标准答案」集合，**不参与训练**，专门用来测效果。它的质量直接决定你验收是否可信。

**怎么构建（面试要能说步骤，这是字节真题）**：
1. **定范围**：从真实业务里采样，覆盖高频场景 + 长尾场景 + 边界/脏 case，不能只挑「简单好答的」。
2. **定标注标准**：写清「什么算对、什么算错、模糊怎么判」，多个标注员要对齐（否则标注不一致，评测集本身就不准）。
3. **标注 + 交叉校验**：两人背靠背标，不一致的拉出来仲裁，算 Kappa 一致性。
4. **分层管理**：按难度/场景/来源分层，方便定位「哪类问题效果差」。
5. **持续更新**：线上新 badcase 定期回流进评测集（评测集会「老化」，要跟着业务走）。

**面试加分点**：能说出「评测集要覆盖边界 case、要算标注一致性、要持续回流」，而不是「找几个人标一下」。

---

### 2. 离线指标 vs 在线指标 —— 两套都要盯，且别混

| 类型 | 是什么 | 指标 | 时机 |
|---|---|---|---|
| 离线 | 评估集上跑，控制变量、可复现 | 准确率 / 召回率 / F1 / BLEU / ROUGE | 上线前 |
| 在线 | 真实用户行为 | 采纳率 / 任务完成率 / 人工接管率 | 上线后 |

**关键认知（常被追问）**：
- **离线好 ≠ 在线好**：离线是「实验室」，在线是「真实世界」，分布不一致会导致离线涨了在线没涨。
- **准确率 vs 召回率怎么权衡**：客服问答「宁可不答也别乱答」→ 重准确率（高 precision，低召回可接受，拒答转人工）；内容推荐「宁可多给别漏」→ 重召回。取舍看业务后果。
- **LLM 评估 LLM 的偏差**：用 GPT-4 当裁判模型打分有偏差（偏爱长答案、自己家族），要加「裁判一致性校验 + 人工抽检 + 多裁判投票」。
- **指标本身不是目的**：北极星是「用户问题被解决」，接管率/准确率都是代理指标，别为了刷代理指标牺牲真实价值。

### 3. 数据闭环 —— 采集 → 清洗 → 标注 → 评估 → 迭代

**为什么重要**：AI 功能上线是验证开始，不是结束。真实数据喂模型才能形成飞轮。

**怎么搭（要能落到具体）**：
- **采集**：埋点记用户输入 + 模型输出 + 用户反馈（采纳/编辑/转人工都是信号）。
- **清洗**：去重、去脏、过滤敏感、对齐格式。
- **标注**：把「用户真实 badcase」标成「标准答案」，回流评测集。
- **评估**：跑评测集看指标变化。
- **迭代**：定位哪类 case 差 → 改数据/改 Prompt/改模型 → 再评估，闭环。

**价值归因（最容易被问懵）**：效果提升了，到底是「模型的功劳」还是「别的因素」？
- 方法：控制变量（同一评测集只改一个变量）、A/B 对照、分层拆解（哪类 case 涨了）。
- 面试话术：「上线后采纳率涨了，我要先确认是模型改对了，还是入口流量/用户结构变了——用同一份评测集离线复现 + 分层看 case 变化来归因。」

## 二、要做什么（落地动作）

1. **搭一个最小评测集**：从你做的 AI 项目里抽 50–100 条真实 case，标标准答案，分「高频/长尾/边界」三层。这是「你具体做了什么」的弹药。
2. **画一张指标看板**：离线（准确率/召回率/F1）+ 在线（采纳率/完成率/接管率）两栏，标清「每个指标在哪个环节看」。
3. **准备一个 badcase 案例**：能说出「用户原输入是什么 → 模型误理解成什么 → 怎么定位 → 怎么改」全链路。字节 Agent 面真实要求「举例用户原输入和误理解」。
4. **练一道手撕题**：RAG 效果评估表（召回率/命中率统计 + badcase 分析 + 优化建议），5 天速成清单里的必考题。

## 三、面试要考什么（真题 + 话术 + 追问链）

**Q1. 如何构建评测集？（字节真题，杀伤力高）**
- 话术：「从真实业务采样，覆盖高频+长尾+边界 case；定清楚『对/错/模糊』的标注标准并多人对齐；标注后交叉校验算一致性；按场景分层方便定位；线上 badcase 定期回流更新。」
- 追问链：评测集会不会老化？（会，要跟着业务回流更新）；标注不一致怎么办？（仲裁 + 算 Kappa）。

**Q2. 用什么指标衡量最终效果？（字节真题）**
- 话术：「离线看准确率/召回率/F1，在线看采纳率/任务完成率/人工接管率。离线验证能力、在线验证价值，两套都要看，且要能解释准确率和召回率的取舍。」

**Q3. AI 功能怎么验收？（概念，高频）**
- 话术：「先定评估集和离线指标（上线前跑）→ 上线看在线指标 → 数据闭环迭代 → 归因到模型。验收不是上线那一刻，是一条持续链路。」

**Q4. 转人工率容易被 mock，怎么处理？（字节真题，见 ⑧ 也考）**
- 话术：「不能用单一转人工率，要交叉校验：问题解决率、一次解决率、满意度，加人工抽检。」

**Q5. 效果提升了怎么证明是模型的功劳？（价值归因，杀伤力高）**
- 话术：「控制变量：同一评测集只改模型一个变量离线复现；上线用 A/B 对照；再分层看哪些 case 涨了。避免把入口流量/用户结构变化误归因给模型。」

**Q6. 调 Prompt 时怎么确认调好了？评估标准是什么？（字节 Agent 真题）**
- 话术：「先定好评估标准（离线评测集 + 关键指标 + badcase 清单），每次调 Prompt 跑同一份评测集看指标，A/B 对比；同时人工看 badcase 是否收敛。不是『感觉变好了』，是『指标动了 + badcase 少了』。」

**Q7. 服务多个 Agent 时如何评估各自好坏？（字节真题）**
- 话术：「按 Agent 的职责分别定指标——比如客服 Agent 看解决率、推荐 Agent 看采纳率；共享的用统一评测集，各自专有的建独立评测集；再叠加一个『整体任务完成率』看协同效果，因为单个 Agent 好不代表协作好。」
