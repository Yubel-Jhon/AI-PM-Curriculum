# ⑧ AI 技术认知 · 深度详解

> 侧重点：判断「能不能做」。这一块是所有 AI-PM 面试的淘汰重灾区，也是最容易「一句话带过」被追问到崩的板块。
> 本文按「有什么内容 → 要做什么 → 面试要考什么」三层拆，每个概念给足缓解方法，不滑坡。

---

## 一、有什么内容（知识地图，每个概念往下走）

### 1. 幻觉 —— 不是「无法根除」就完了，要看你怎么压

**本质**：大模型做的是「下一个词预测」，不是查数据库。它生成的是「概率上最像人话」的内容，而不是「事实」。所以幻觉是生成机制自带的，不可能 100% 消除——但这句话是**起点**，不是**终点**。

**先分清两类幻觉（解法完全不同，这是第一层筛选）**：

| 类型 | 根源 | 典型表现 |
|---|---|---|
| 检索层幻觉 | 没召回 / 召回不全 / 召回了错的 | 模型凭参数里背过的知识「编」，答非所问、张冠李戴 |
| 生成层幻觉 | 召回到了，但没严格照着说 | 自己加料、篡改数字、把 A 文档的内容安到 B 上 |

**缓解方法（按成本从低到高，四层，面试要能背出这个顺序）**：

1. **Prompt 层**（几乎零成本）：强约束「只根据给定资料回答，资料没有就明确说『我不知道』」；few-shot 给「拒答示范」；角色设定 + 输出格式锁定。
2. **检索层**（治检索层幻觉）：切片优化（chunk 大小/重叠，语义切分优于固定长度）；多路召回（向量 + 关键词 BM25 + 稀疏检索取并集）；**Rerank**（cross-encoder 对召回结果重排序、剔除不相关）；**召回质量门控**——相似度低于阈值就拒答，而不是硬编。
3. **生成层**（治生成层幻觉）：**引用核查**——要求每个结论标注来源 chunk，可逐条比对；**结构化输出**——用 JSON schema 强制字段，不让它自由发挥；调低 temperature；后验校验——另起一个模型/规则检查「生成是否忠于检索结果」。
4. **产品层兜底**（最后一道）：不确定时明示「我不确定」+ 转人工；免责声明；高敏场景（医疗/法律/金融）强制 human-in-the-loop。

**边界与误区**（面试常被追问）：
- ❌「检索做好就不会幻觉」——外行话。检索好只能消检索层幻觉，生成层照样可能乱编。
- ❌「换个更大的模型就不幻觉了」——幻觉是概率生成的本质，不是规模问题，只能压不能灭。
- ✅ 正确口径：幻觉率能压到可接受区间，靠的是「门控 + 溯源 + 兜底」组合拳，不是单一手段。

**衡量指标**：幻觉率、忠实度（faithfulness，生成内容对检索源的忠实程度）、引用准确率。

### 2. RAG —— 三步之外，面试考的是「落地细节」

**三步骨架**（一定要会）：索引（切 chunk + embedding 建向量索引）→ 检索（问题与 chunks 相似度召回 + rerank）→ 生成（以检索到的上下文为条件生成）。

**但面试真正考的是这些落地细节**（来自字节智能客服真题）：

- **为什么建了向量库还要保留 FAQ？** FAQ 管高频、标准、确定的问题（快、可控、答案稳）；向量库管长尾、模糊、开放问题。两者互补：FAQ 兜底确定性场景，向量库接长尾。别答成「二选一」。
- **切片策略**：固定长度 + 重叠（防切断语义）vs 语义切分（按段落/标题）；chunk 太小丢上下文、太大稀释相似度——面试要能说「我按什么粒度切、为什么」。
- **混合检索**：纯向量检索对「专有名词、精确匹配」弱，加 BM25/关键词路做并集，再 rerank 提精度。
- **Query 改写**：多轮对话里「它多少钱」要改写补全成「XX 产品多少钱」再检索，否则召回全歪。
- **知识时效性**：定时/增量重建索引、过期文档下线、版本管理（对应「知识怎么保证最新」）。
- **Rerank 的作用**：不牺牲准确率的前提下加速查询——剔除不相关节点、重排相关节点（同时往往还能提准确率）。

**微调 vs RAG（最高频选型题，别只背定义）**：

| 维度 | RAG | 微调 |
|---|---|---|
| 知识存哪 | 外部向量库（动态） | 模型参数（固化） |
| 更新 | 换库即可，秒级 | 重训，贵且慢 |
| 可溯源 | 强，能指到 chunk | 弱，黑盒 |
| 适用 | 知识更新快、要溯源（客服/问答） | 垂直领域深度适配、格式/语感要稳定 |
| 一句话 | 开卷考试 | 把书背下来 |

**结论口径**：业务知识更新比翻书快 → RAG-First；跑通后发现「语感不对 / 格式不达标 / 领域风格化」再上微调，两者不是互斥，是先后。

### 3. Agent —— 四层架构 + multi-agent + reflection

**定义**：Agent = 大模型 + 规划（Planning）+ 工具调用（Tool Use）+ 记忆（Memory）+ 反馈（Feedback）。最易翻车在「计划瞎定目标」和「反馈给错判断」两环。

**四层架构**（面试官视角满分答法，来自真实面经）：
1. **规划层**：ReAct（边想边做，一步步推理）vs CoT（预设关键步骤）vs Plan-and-Execute（先定计划再执行）——决定 Agent 是「死执行」还是「活思考」。
2. **工具层**：不只是接入 API，关键是**工具编排策略**——查不到直飞时自动查中转，还是立即问用户？预设决策流。
3. **记忆层**：区分**工作记忆**（当前任务上下文）和**长期记忆**（向量库存偏好/历史），规划时主动检索。
4. **状态与评估层**：能汇报进度、卡住时触发预设降级，而不是沉默或崩溃。

**一句话点题**（面试官最吃这句）：「传统产品是确定流程，像铺铁轨；Agent 是未知地形自主导航，我的工作是定义导航、配工具、设应急原则。」核心 = **对不确定性的管理**。

**Workflow vs Agent（2026 高频新题）**：
- Workflow = 预设固定流程，确定性、可控、可调试、成本可估 → 适合流程明确的场景。
- Agent = 模型自主规划决策，灵活但不可控、易跑偏 → 适合开放任务、规则难穷举。
- 为什么选 workflow 不选 Agent：确定性与成本可控；为什么选 Agent：任务开放、规则穷举不完。

**multi-agent（多智能体）—— 深度加分项**：
- 思路：单个 Agent 能力有限且易「一个模型既要规划又要执行还要自查」，拆成多个专职 Agent 分工。
- 常见编排模式：**Orchestrator-Workers**（主从，一个调度多个执行）、**Peer-to-Peer**（对等，互相调）、**Hierarchical**（分层，层层下放）。
- 代价：多 Agent = 多倍 token 成本 + 一致性问题 + 通信开销。**能单 Agent 解决的不要上多 Agent**——这是产品判断，不是越复杂越好。

**reflection（反思）—— 深度加分项**：
- 思路：让 Agent 生成后自我评估 → 反思 → 重试，形成「生成-批判-改进」循环（如 Reflexion 范式）。
- 用途：提升生成质量、纠错、缓解幻觉；典型 prompt 结构是「先给出答案 → 再以审稿人视角挑错 → 基于挑错重写」。
- 面试能说清 reflection 和「多轮重试」的区别（reflection 有「显式的自我批判中间产物」，不是无脑重试）就很加分。

**MCP / Skills（2026 新考点，往年没有）**：
- **MCP**（Model Context Protocol）：统一「模型 ↔ 工具/数据源」的接入协议，让工具调用标准化、可插拔。
- **Skills**：给 Agent 的可复用能力封装（指令 + 工具 + few-shot 示例），把一次性操作变成可反复调用的技能。写 Skills 三步：定触发条件 → 写清步骤与工具 → 给示例。
- **vibe coding**：用自然语言描述意图让 AI 生成代码，人负责目标与验收。价值 = 快速验证想法；边界 = 出 bug 看不懂改不动，适合 demo 验证不适合生产系统。

### 4. 大模型基础 —— 会到「能接住追问」的深度即可

- **Transformer**：自注意力（Self-Attention）让每个词能直接看到所有词 + 并行计算，解决 RNN 长序列遗忘。
- **预训练 → 微调 → Prompt**：预训练学通用语言能力 → 微调往特定任务/领域靠 → Prompt 现场注入指令（不碰参数）。
- **LoRA**：低秩适配，冻结原模型只训少量低秩矩阵，大幅降微调成本——面试说「为什么 LoRA 不全量微调」就考这个。
- **GRPO**（群体相对策略优化）：省掉价值网络、用组内相对奖励，降强化学习训练成本；DeepSeek 用 GRPO + MoE（混合专家）+ MLA 降推理成本——字节抖音面真实考过。
- **上下文窗口**：窗口大 ≠ 什么都塞。长文档要么分块 + RAG，要么用长上下文模型（但贵且慢）；**延迟决定交互形态**（流式输出、缓存、小模型先答）。

## 二、要做什么（落地动作，不是背概念）

1. **每个概念配一个「类比 + 选型理由 + 边界 + 一个真实场景」**，写进你自己的话术卡片。类比：RAG=开卷考试、微调=背书、Prompt=小抄、幻觉=一本正经编。
2. **亲手做 1 个 RAG demo**：切分 → 向量库 → 召回 → rerank → 生成，记录「漏召回 / 幻觉 / 答不规范」三个坑和你的解法。这是面试官问「你具体做了什么」时的弹药。
3. **亲手写 1 个 Skills / 用 vibe coding 搓 1 个 demo**：2026 每场必问「写过 Skills 吗」，没做过答不出细节。
4. **准备一个「AI 工具横向认知」万能答案**：ChatGPT / Claude / Kimi / 豆包 各能说清「交互逻辑 + 产品定位 + 一个改进点」。

## 三、面试要考什么（真题 + 话术 + 追问链）

**Q1. 怎么解决幻觉？（概念，杀伤力高，高频）**
- 话术：「幻觉不是撒谎，是模型生成『看起来合理的下一个词』。先分两类——检索没捞到（检索层）还是没照抄（生成层），根源不同解法不同。低成本四步：Prompt 强约束 → 检索质量门控（Rerank 低于阈值拒答）→ 生成后引用核查 → 结构化输出强制溯源。生产系统前两个必须上，后两个看场景。」
- 追问链：检索做好是不是就没幻觉了？（不是，生成层照样编）；怎么量化幻觉率？（忠实度/引用准确率）。

**Q2. RAG 和微调怎么选？（概念，杀伤力高，高频）**
- 话术：「微调把整本书背下来（黑盒、更新要重训、贵），RAG 是开卷考试（外挂向量库、换库不换脑、可溯源）。业务知识更新快，RAG-First；跑通后发现语感/格式不达标再上微调。」
- 追问链：RAG 效果不好怎么排查？（切片 → 召回 → 重排三层，逐层定位）。

**Q3. 为什么建了向量知识库还要保留 FAQ？（字节智能客服真题，杀伤力高）**
- 话术：「FAQ 管高频标准问题，确定、快、可控；向量库管长尾模糊问题。FAQ 兜底召回失败的确定性场景，两者互补，不是替代。」

**Q4. 转人工率容易被 mock，怎么处理？（字节真题）**
- 话术：「客服把用户晾着或重复转人工，就能刷低转人工率。所以不能只看单一转人工率，要用真实业务指标交叉校验：问题解决率、一次解决率、用户满意度，再配合抽样人工质检。」

**Q5. 智能客服如何保证知识时效性？（字节真题）**
- 话术：「定时/增量重建索引、过期文档下线、版本管理，配合知识库运营流程——谁维护、多久审一次、变更怎么同步到线上。」

**Q6. Agent 和 Workflow 区别？为什么用 workflow 不用 Agent？（2026 新题，杀伤力高）**
- 话术：「本质区别是确定性 vs 自主性。Workflow 预设固定流程、可控可调、成本可估；Agent 自主规划、灵活但易跑偏。流程明确选 workflow，任务开放规则难穷举才上 Agent。」
- 追问链：什么场景一定不能上 Agent？（高风险、需强确定性的场景）；Agent 跑偏了怎么兜底？（降级策略 + 状态评估层）。

**Q7. 什么是 Skills？怎么写？（2026 每场必问）**
- 话术：「Skills = 给 Agent 的可复用能力封装（指令+工具+示例），把一次性操作变成可反复调用的技能。写三步：定触发条件 → 写清步骤与工具 → 给 few-shot 示例。用 AI 生成 = 先把需求/工具说清让 AI 出初稿，再人工校验边界和失败处理。」

**Q8. 设计一个旅行规划 Agent，从哪些层面考虑？（面试官视角，杀伤力高）**
- 话术：「四层：规划层（ReAct 自主想 vs CoT 预设步骤）、工具层（编排策略，查不到直飞是自动中转还是问用户）、记忆层（工作 vs 长期记忆，向量库存偏好主动检索）、状态评估层（汇报进度 + 卡住降级）。核心是管理不确定性——Agent 是自主导航，不是铺铁轨。」

**Q9. 对 vibe coding 的理解？（2026 新题）**
- 话术：「自然语言描述意图、AI 生成代码，人负责目标与验收。价值是快速验证想法、降门槛；边界是出 bug 看不懂改不动，适合 demo 不适合生产。」

---

> 一句话收口：AI 技术认知 = 把「我有个 AI 想法」翻译成「模型任务 → 能力边界 → 可行性 + 风险点」。背定义过不了关，能说出「怎么压幻觉、怎么选型、怎么兜底」才过。
